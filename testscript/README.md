# testscript — 测试脚本目录

本目录存放本项目**全部 289 个测试脚本**（`t_*.js`）及其共用的 `_harness.js`。

这些脚本是**开发/验收用**，不是运行时文件——页面加载不依赖它们，删掉不影响加解密功能。
放进交付包是为了让你在解压后能**自己复算**，不用只信我报的数字。

---

## 怎么跑（重要）

**必须在本目录的上级目录（即 `index.html` 所在的那层）运行**，不能 `cd testscript` 再跑：

```bash
cd 解压后的根目录        # 就是 index.html 所在的目录
node testscript/t_aes.js
```

原因：脚本内部用 `readFileSync('index.html')`、`readFileSync('testvectors/...')`
读取实现清单和官方向量，这些路径是**相对当前工作目录**的，只有在根目录执行才找得到。

`require('./_harness.js')` 这类引用是相对脚本自身位置的，已经在移动时统一修正过，
所以在哪儿执行都没问题。

## 常用脚本

| 脚本 | 用途 |
|---|---|
| `t_ST.js` | 冒烟测试：全部条目走注册入口加密→解密，比对能否还原 |
| `t_SCT.js` | 侧信道时序：扫非常数时间比对 + 动态测标签位置时序 |
| `t_diff.js` | 差分测试：以 Node 内置 crypto 为独立裁判 |
| `t_SPT.js` | 状态污染测试：扫全局可变状态是否被跨调用残留 |
| `t_aegis.js` | AEGIS 系列官方 KAT |
| `t_mce_kat.js` | McEliece 348864 官方 KAT（含 NIST DRBG 派生） |
| `t_drbg_entry.js` | Hash/CTR-DRBG 条目层验收 |

**三件套**（Reg / ST / SCT）是每次更新必跑的，其中 Reg 由 `_reg.sh` 批量驱动。

## 关于失败项

不是所有脚本都能在干净环境里跑通，已知三类原因，**都不代表算法实现有问题**：

1. **依赖包外文件**：部分脚本硬编码了 `/data/workspace/...` 绝对路径（工作区专属），
   在你机器上必然 `ENOENT`。这类脚本以我工作区的实测结果为准。
2. **依赖未随包发出的向量**：个别向量体积过大或授权不明未打包。
3. **脚本自身过期**：断言里写死了旧的算法总数之类。

判断一个算法到底对不对，请以**有官方向量的脚本**输出为准。
