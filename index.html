输出格式与模式说明（23 种编码 / XTS / IGE / Argon2）
输出格式（23 种，任选）：Base64、Base64URL、Base64（MIME 76 换行）、Hex 小写/大写/空格分隔/冒号分隔、C 数组、十进制数组、JSON 数组、二进制串、转义串、Base32、Base45、Base58、Ascii85、Z85、UUEncode、Hex dump、Python bytes、Go []byte、Rust 数组、PEM。加密与解密要选同一种格式，否则解析会出错；其中 UUEncode / Hex dump / 三种语言字面量只能编码、不能反向解码，别用于要解密的密文。

IGE 模式：Infinite Garble Extension（OpenSSL 的 -ige），C_i = Enc(P_i ⊕ C_{i-1}) ⊕ P_{i-1}，一个字节出错会污染后面全部块。IV 框要填 32 字节（AES 块长 16 的两倍）：前 16 字节是明文反馈初值，后 16 字节是密文反馈初值；留空会随机生成并回写。实现按定义编写并与独立 Python 实现交叉验证一致（OpenSSL 3 的 enc 命令已不提供 ige，未能与官方直接对拍）。

XTS 模式（磁盘加密）：IEEE 1619 标准，用于磁盘/扇区加密。选 XTS 后，IV 框里填的就是 tweak（16 字节），留空会随机生成并回写。特点：不填充，密文长度 = 明文长度；明文至少 16 字节；只支持 128 位块算法（AES/Serpent/Kuznyechik/Camellia/Twofish/SM4 等），DES/Blowfish/IDEA 会明确拒绝。

Argon2（内存硬 KDF）：RFC 9106，抗 ASIC/GPU 暴力破解，强于 PBKDF2 和 scrypt。用法：输入栏填盐（至少 8 字节），密钥栏填口令，参数栏填 轮数,内存KB,输出字节数（如 2,1024,32）。三种变体：Argon2id（推荐）、Argon2i（抗侧信道）、Argon2d（抗 GPU 最强）。
性能提示：本实现用 BigInt 做 64 位运算，1MB/2 轮约 0.24 秒；内存开得越大越慢，建议先用 1024 以内试。
本批新增：填充 / 模式 / 容器 / 密钥导出 使用说明
填充模式（9 种）：PKCS7、PKCS5（8 字节块）、ISO 10126（随机）、ANSI X9.23、ISO/IEC 7816-4、TBC（尾位补码）、ESP（RFC 4303）、Zero、无填充。
填充校验：默认严格——填充字节不符合规范就直接失败，这是防御 Padding Oracle 的正确姿势。切到宽松会容忍错误填充，但那本身就构成了攻击面，仅供排查旧数据。

新增加密模式：
· PCBC：错误会向后传播，一个字节损坏污染后续全部块。
· LRW：IEEE P1619，XTS 的前身，tweak 用 GF(2128) 乘法算，IV 框填的是起始 tweak。
· CTS-CS1/CS2/CS3：密文窃取，密文长度 = 明文长度（不填充）。CS1 是 NIST 变体，CS3 是 Kerberos5（RFC 3962）。明文至少 1 个块。
· CFB8 / CFB1：SP 800-38A 的 CFB 变体，按字节 / 按比特处理，无需填充。CFB1 极慢，仅小数据。
· XTS / LRW 只支持 128 位块算法；DES、Blowfish、IDEA 会明确拒绝。

封装格式：
· IV‖密文：把 IV 直接拼在密文前面，解密时自动切分，不用另外保存 IV（ECB 无 IV，不适用）。
· OpenSSL 无盐：等价于 openssl enc -nosalt，密钥走 EVP_BytesToKey(SHA-256) 但不带 Salted__ 头，密文更短、可复现。
· JSON 全参数：{v,alg,mode,pad,iv,salt,ct}，算法/模式/填充/IV/盐全在里面，解密时自动读取，最省事。
· PEM 装甲：-----BEGIN CIPHER----- 包一层 Base64，纯文本封装，不携带 IV。
· OpenSSL 兼容：输出 Salted__ + salt + 密文，密钥走 EVP_BytesToKey(SHA-256)，可与 openssl enc -md sha256 互通。
· CryptoJS JSON：{ct, iv, s}，密钥走 EVP_BytesToKey(MD5)，与 CryptoJS 默认一致。
· PGP ASCII Armor：带 CRC24 校验，篡改会被抓到。
· JWE：RFC 7516 紧凑序列化（alg=dir + A256GCM），五段式。
· 注意：PGP / JWE 不携带 IV，加密后请把 IV 框里的值一并保存。

Salt：填了就参与密钥派生（可与对端约定固定值）；选 OpenSSL / CryptoJS 容器时会自动生成并回写。
AEAD 标签长度：默认 16 字节；8 字节及以下安全性明显下降，仅用于互通或测试。
nonce 复用检测（GCM / CCM）：加密时登记用过的 (密钥指纹, nonce)，第二次撞上就直接中止。同一密钥 + 同一 nonce 加密两段明文，会泄露两段明文的异或，并能反推出 GHASH 的认证密钥 H 从而伪造标签——这是 GCM 最严重的误用。记录存在浏览器本地，只保存密钥的 SHA-256 指纹，不保存密钥本身或任何明文。切换密钥或清空记录后该组合可再次使用。
· 阻止（默认）：发现复用立即中止；仅警告：照常加密但红字提示；关闭：不检测。
· 另一个相关改动：IV 框里自动填入的值只供你保存，再次加密会自动换新的（不会误用上一次的 nonce）；只有你手动填写或修改过的 IV 才会被实际采用。
· SIV 是确定性 AEAD，本身抗 nonce 误用，不参与检测。

密钥栏的 6 种输入方式：
· 口令（默认）：走下面选的 KDF 派生，Salt 框可固定盐以便复现。
· 原始密钥 Hex / Base64 / 文本 UTF-8 / 十进制数组：不经 KDF，长度必须正好等于算法要求（AES-256 就是 32 字节），否则明确报错而不是静默截断。
· 随机生成：密钥框留空即可，加密时生成符合长度的随机密钥，并把实际用到的密钥回写到密钥框（同时切到 Hex 模式），方便保存复用。

密钥对导出：算法选「密钥工具 → 密钥对导出（JWK / PEM）」，参数栏填 p256 / p384 / p521 / rsa2048，点【加密】即输出 JWK 与 PEM 两种格式。私钥 PEM 高度敏感，切勿外传。
